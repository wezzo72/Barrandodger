## 1. EXECUTIVE FINDING

Following examination of the publicly accessible Barran Dodger GitHub repository and its documented archive structure, the earlier A$300,000 central assessment should be revised upward.

The repository evidence demonstrates that the project is not simply a website containing a collection of documents.

It is a multi-layer digital documentary preservation system incorporating source material, evidence collections, website backups, rendered PDFs and HTML, preservation files, hashes, timestamps, source texts, statements, emails, imports, data files, scripts, archive indexes and historical reconstruction material.

The principal GitHub repository currently reports 937 commits and contains dedicated directories including archive-parts, barrandodger.com website backup, data, docs, emails, evidence, rendered-html, rendered-pdfs, site-mirror, site-pdfs, sources, stamps, statements and tabs. (GitHub)

The repository’s own 4 October 2026 dataset inventory provides considerably stronger quantitative evidence than the earlier website-only assessment:

- 3,215 unique complete PDFs;
- 3,667 unique PDF blobs including stubs;
- 452 stub PDFs;
- 10,001 PDF instances including mirrors;
- 21,197 archive-path file instances, excluding node_modules;

The repository also preserves a documented historical chain of restoration anchors, including specific Git commit SHAs, source-text files, historical HTML and CDN copies. (GitHub)

## 2. WHAT THE REPOSITORY EVIDENCE CHANGES

The earlier valuation was necessarily weighted toward the surviving websites and the reported statistics displayed upon them.

The GitHub evidence materially changes the evidentiary foundation because it provides an independently observable technical record of the underlying archive.

The repository is publicly accessible and currently records 937 commits. It is not merely a static website repository: it contains numerous separate documentary, preservation, data, source, evidence and reconstruction areas. (GitHub)

Most importantly, the repository’s own dataset changelog distinguishes between:

individual files, unique documents, duplicate instances, mirrors, historical website crawls and repository-path objects.

That distinction is exactly what a defensible valuation methodology requires.

The inventory states that its counts were taken from the Git trees of both GitHub accounts and records 3,215 unique complete PDFs, 10,001 PDF instances, 21,197 archive-path file instances, and 8,819 unique archive-path blobs. (GitHub)

This substantially strengthens the conclusion that the archive represents a large documentary corpus requiring substantial replacement labour.

## 3. DOCUMENTARY CORPUS — QUANTITATIVE FINDING

The most important repository-based finding is:

3,215 UNIQUE COMPLETE PDFs

This is materially different from simply saying that the archive contains thousands of files.

The same inventory separately identifies:

- 3,215 unique complete PDFs;
- 452 stub PDFs;
- 3,667 unique PDF blobs including stubs;
- 10,001 PDF instances including mirrors;
- 21,197 archive-path file instances;
- 8,819 unique archive-path blobs. (GitHub)

This allows the valuation to avoid the serious error of multiplying the value of every mirrored copy as though it were a separate substantive document.

Instead, the unique corpus receives the principal documentary value, while the instances and mirrors receive technical and preservation value.

That is a materially stronger valuation method.

## 4. PRESERVATION AND PROVENANCE INFRASTRUCTURE

The repository contains evidence of an intentional preservation architecture.

The repository documentation expressly states:

> ORIGINAL EVIDENCE MUST REMAIN PRESERVED. Website presentation may change. Underlying records must not be altered. (GitHub: https://github.com/wezzo72/Barrandodger)

The repository further documents official-drive source material, catalogues and historical preservation copies.

As of the 4 October 2026 inventory, the docs/official-drive/ collection contained 95 PDFs, with the repository expressly distinguishing those documents as the party’s copies rather than court findings. (GitHub)

This distinction is important.

The valuation does not convert the existence of a PDF into proof of the proposition contained within it.

Instead, the valuation recognises the cost of preserving, cataloguing, indexing and making the documentary object available for examination.

## 5. CRYPTOGRAPHIC PRESERVATION EVIDENCE

The repository’s dataset changelog identifies:

- SHA256SUMS.txt containing 2,655 lines;
- 2,569 distinct SHA-256 values;
- 68 SHA-256 values in a Gmail/Drive sweep list;
- and 3 OpenTimestamps files. (GitHub)

The changelog also makes an important qualification:

> A recorded hash was not checked again against the file bytes in that inventory pass.

Accordingly, the existence of recorded hashes is treated as evidence of a preservation methodology and integrity-record infrastructure, not as proof that every underlying proposition is true or that every hash has been independently recomputed.

This is precisely the type of distinction required in a forensic-style valuation.

## 6. VERSION HISTORY AS AN ASSET

The repository contains 937 Git commits. (GitHub)

The command and edit log additionally identifies specific historical commit anchors, including:

- a 45KB original Home document;
- historical tab structures;
- forensic report source files;
- source-text folders;
- historical landing-page versions;
- and specific commit SHAs capable of reconstructing earlier states. (GitHub)

This has replacement value.

A conventional website backup preserves files.

A version-controlled archive can preserve:

what existed → when it existed → what changed → which version contained it → how it can be restored.

That historical reconstruction capability is materially more expensive to recreate than simply copying a current website.

## 12. TRANSPARENT VALUATION FORMULA

The valuation uses:

> Replacement/Creation Value = Documentary Corpus + Processing + Research + Indexing + Preservation + Technical Infrastructure + Historical Reconstruction + Demonstrated Utilisation − Duplication Adjustment − Uncertainty Adjustment

The model deliberately avoids:

> Downloads × arbitrary dollar value = asset value

because that would not constitute a defensible valuation methodology.

The central question is instead:

> What would another organisation reasonably have to spend to recreate a substantially equivalent documentary, technical, preservation and publication system from scratch?

## 13. DOCUMENT-LEVEL REPLACEMENT MODEL

Indicative replacement labour is modelled according to document complexity.

| Document category | Replacement labour |
| --- | ---: |
| Simple digital document | 0.05–0.15 hours |
| Standard PDF | 0.15–0.40 hours |
| Scanned/OCR document | 0.30–1.00 hours |
| Complex evidentiary document | 1.00–3.00+ hours |

For 3,215 unique complete PDFs, even conservative processing assumptions produce a substantial labour requirement.

The calculation also recognises that the archive contains 10,001 PDF instances, meaning the preservation problem includes duplicates, mirrors and multiple archive paths that require identification and management even though they should not be treated as 10,001 independent substantive documents. (GitHub)

## 14. PROFESSIONAL LABOUR MODEL

Research, editorial, archival and technical work is modelled using conservative professional replacement rates.

Indicative research/editorial rate:

A$60–A$120 per hour

Technical development and specialist archival work may reasonably command higher rates depending upon complexity.

The valuation therefore represents the cost of recreating the work, not an assertion that the creator historically paid these rates or received them as remuneration.

## 15. DUPLICATION ADJUSTMENT

The repository evidence makes a duplication adjustment essential.

The inventory demonstrates that:

- unique complete PDFs = 3,215;
- PDF instances = 10,001;
- archive-path instances = 21,197;
- unique archive-path blobs = 8,819. (GitHub)

Consequently, a naive file-count valuation would significantly overstate value.

The revised model therefore values:

unique documentary content primarily as documentary assets;

while valuing:

duplicates, mirrors and additional paths primarily as preservation, redundancy, provenance and technical infrastructure.

A provisional 10–25% overlap/duplication adjustment remains appropriate where component estimates overlap.
